# Individual advert evidence reviews

The owner dashboard's **Advert reviews** desk holds one original advert when its application deadline, sponsorship wording or availability conflicts with other evidence. It supports built-in sources and configured employer feeds, including a pending school before its first publication. It never creates an employer, approves its licence, relaxes source parsing or changes sponsorship wording.

A decision needs a configured source, exact supported public advert link, title, conflict category, public evidence link, evidence note and observation within 72 hours. A hold needs a follow-up within seven days; the due date does not release it. Release requires a new explanation and evidence observed after the previous decision. Notes must exclude applicant information, CVs, credentials and session identifiers. The evidence link is recorded for manual review, never fetched by this endpoint. Only documented public query-routing fields are accepted.

Each decision appends an immutable revision and an audit entry in the same transaction. Request keys handle lost acknowledgements; optimistic revision checks prevent concurrent sessions overwriting each other. The owner identity and same-origin write boundary remain. Initial decisions can only hold an advert; there is no delete or bulk-release endpoint. The queue has a 500-advert limit and bounded list/history pagination.

Database triggers immediately retire matching existing jobs and suppress held adverts during later full source imports. A review can precede the first import. Once a source advert has matched, its stable job ID remains linked to the review even if its URL changes. A pre-import hold only knows its exact supplied URL until that first identity match; it cannot infer an entirely changed URL or a new provider job ID. Those cases need separate review.

Releasing a hold leaves the old snapshot inactive. A successful complete source collection started after the decision must observe the advert again before it returns. Older in-flight results, later request replays, and elapsed follow-up dates cannot reactivate it. Review logic never bypasses a malformed catalogue, failed employer identity check or contradictory text that already fails source validation. An absence on the next feed still leaves the role inactive.

Held roles are absent from the current jobs collection, opportunity counts, sitemap, research selection and saved-search matches through their inactive state. Historical detail links remain with a clear review/waiting notice, noindex metadata and paused preparation. Only the review state is public; evidence notes, reviewer identity and history remain in the owner desk. Existing personal application workspaces are preserved. Already generated documents or externally delivered posts are not automatically recalled.

The source receipt retains the complete collected count and the separate number of adverts on review hold. Owner source history therefore labels these as **Collected roles**. The hourly business snapshot records aggregate hold/due counts; overdue reviews create a normal-priority finding without copying notes or links. Holds are created and resolved by evidence review, not by a model acting on untrusted advert instructions.

## Validation and deployment boundary

The isolated tests cover immediate retirement, pre-import holds, URL changes after identity matching, independent unaffected roles, new-evidence release, in-flight refresh ordering, historical replay, concurrent decisions, audit rollback, immutable history, overdue findings, restricted links and public metadata. The actual Cloudflare SourceWorkflow/D1 runtime reads a complete fictional school catalogue, retains one held advert privately, publishes the other, records the hold count and replays with no additional provider calls. Browser verification uses fictional records: release remains inactive, history is retained and the review form fits 390px without horizontal overflow.
