# Saved applications and changed adverts

Release 2.85 adds a reviewed source version to saved catalogue applications. It hashes the complete collected description, employer, role, location, original destination, sponsorship label/quote, deadline, salary and working arrangement. Observation timestamps are excluded: a successful unchanged refresh is not a wording change. The version is based on the stored collection, not a fresh external employer request or independent semantic review.

Reopening or saving an existing role selects its application without replacing its working text. Studio compares its saved version with the latest available record. A changed version pauses new preparation and displays the current role facts and both texts. Older copies without a version are usable when their working advert exactly matches; otherwise the interface asks for review without claiming the employer caused the difference.

The user may explicitly use the latest advert, or compare and confirm keeping edited working text. Both choices update current role metadata, original link, sponsorship evidence and source version. Notes, master CV, generated documents, stage and follow-up remain intact. A concurrent working-advert edit prevents accepting a stale comparison. Neither action regenerates or certifies existing drafts. Preparation from a deliberately retained working description still needs the user's factual review.

Source text above the 26,000-character workspace limit is displayed in full for comparison, cannot be silently adopted/truncated, and needs reviewed excerpts. New long-source saves have no automatic version acknowledgement. A change beyond that limit still changes the fingerprint. CV refusal checks also inspect the complete current collected advert, so retaining older edited text cannot remove a recognized current application-format restriction.

The server checks availability and source version before allowance charging, after company research or the first model stage, and before returning a completed draft. Later changes stop further output while keeping consumed reservations. Client checks occur on load, visible periodic checks and immediately before preparation; session/input guards still reject late results after user edits. Manual UUID/legacy blank applications retain their declared unverified-source behavior. Held, closed, missing and stale catalogue roles remain blocked.

The optional version travels through normal private workspace validation, sync, import/export and existing revision checks; no schema migration, new model, permission or budget is needed. It is user-editable workspace metadata, not an independent audit of a person's review. No private input goes into the public availability response, which contains only current public advert fields. No workspace write, production model call or synthetic customer activity is required for release verification.

Rollback to 2.84 preserves notes and documents but removes this comparison/guard and restores its old saved-role reopening behavior. Older workspace validation can drop the optional source version on a later save; a subsequent upgrade will treat that copy as legacy and may ask for review again. Do not claim rollback preserves this new capability.
