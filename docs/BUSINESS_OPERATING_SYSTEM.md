## Operating model

The cloud handles repeatable production work. A daily Codex follow-up handles bounded engineering, research and growth improvements. The owner dashboard distinguishes observed receipts from configured schedules and blocked connections. This is an initial operating layer, not proof of an independently profitable, fully autonomous company.

The hourly workflow uses a stable hour identifier, a single-active-run database constraint, durable steps, stored snapshots and atomic publication receipts. Confirmed terminal workflows can release a stale active run; an unknown platform response never starts a second copy. A retry of a paid model call cannot silently bypass its existing reservation. Research dispatch is reserved once per UTC day, including failures or a consumed allowance.

The owner can pause business operations, automatic reports or scheduled research individually. A pause is checked before each mutating area; an already completed action remains recorded. Job and immigration refresh schedules are independent of the business switch. Withdrawing the report removes its searchable article and sitemap entry, supersedes unsent drafts and pauses future publication. It does not erase the retained evidence versions.

## Publishing and search quality

The first report has one stable address: `/insights/uk-sponsorship-jobs-report`. Each publication stores the true measurement time, a previous snapshot comparison when available and its contributing boards. Refresh the useful report rather than multiplying near-identical weekly URLs. The visible report and Article metadata agree. Unavailable or withdrawn articles return 404/410 with noindex. The insight hub, live article, feed and job pages are crawlable without JavaScript.

Do not call catalogue growth overall UK market growth, event counts unique visitors, a licence a sponsorship offer, positive advert wording personal eligibility, or unpublished drafts live social posts. Source health is not independently measured classification accuracy. Avoid duplicate SEO pages, purchased links, fake reviews, arbitrary date changes and unsupported “number one” claims. Google's [generative-AI content guidance](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content) asks for useful added value; [spam policies](https://developers.google.com/search/docs/essentials/spam-policies) cover scaled content abuse.

Routine editorial expansion should start with original advert-quality audits, transparent source-coverage improvements and tested product tutorials. Immigration changes require exact official sources, dates, affected audiences, source-version checks and qualified review where interpretation or personal circumstances matter. Do not feed private CVs, legal questions, email addresses or user feedback into a public article or social draft.

LinkedIn job sourcing is a different integration and remains subject to the existing permitted-feed pilot.

Once connected: inventory only the relevant brands/accounts; match them with the owner's destinations; confirm the concrete permission screen when required; publish one useful, current report post per intended account; store returned post ID, exact destination, timestamp and delivery result. Confirm a timeout through provider history before retrying. Never treat a local outbox status as proof of external delivery. Do not bulk DM, send unsolicited campaigns or create new terms-bearing accounts without the necessary confirmation. Organic drafts can be prepared now; paid promotion has no approved budget.

## Daily improvement priorities

1. Reliability: fix real incidents, verify scheduled execution, resolve held feeds, and make external uptime alerting independent of the worker. No email/SMS incident channel is connected yet; dashboard findings and the Codex follow-up are the current escalation surfaces.
2. Quality: complete the 50-advert review and 20 CV/advert benchmark, expand current source coverage through approved employer feeds, and strengthen the research critic to review every narrative claim. The right-to-work-only summary failure from 2.11 remains an explicit regression to close.
3. Activation: test the complete job → evidence → saved application → studio → export journey and improve the largest observed friction. Aggregate event totals include testing activity and are not acquisition attribution.
4. Search: connect read-only Search Console metrics; track relevant non-brand impressions, clicks, index coverage and real conversions. Current crawlable HTML, schema and sitemap are technical groundwork, not evidence of ranking gains.
5. Distribution: connect the verified company and personal accounts, publish useful posts, collect actual performance, and prefer repeatable channels that produce useful applications over vanity impressions.
6. Premium: validate trustworthy personalised alerts, saved employer research, high-quality application review and appropriate adviser referrals with willing users. Define the offer, support workload, pricing and refund terms before a payment integration. No revenue or customer willingness-to-pay has yet been demonstrated.

For each change record the problem, hypothesis, evidence, action, verification, result window and whether it helped. New model or prompt versions require versioned evaluations and comparison with the prior baseline. Do not describe remembered approved observations as self-modified model weights or uncontrolled evolution. Expand authority only after measured success in that area.

## Current security and delivery limitations

The 7 October production dependency audit reports three moderate dependency entries from one underlying advisory: `mammoth → argparse → sprintf-js`, [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). No patched sprintf-js version was listed. The identified argparse usage is the Mammoth CLI dependency; Sponsor Intel imports its document library, not the CLI. Do not force npm's suggested downgrade to Mammoth 0.3.29. Reassess the dependency path and an appropriate upstream release or replacement in the daily security review; this is a tracked finding, not a clean audit or a proven live exploit.

GitHub CI previously did not start because of an account billing lock. Verify current check annotations before describing its state. Passing local tests does not repair hosted CI billing. Account emails previously landed in spam; inbox placement remains separate from transport success. No new premium-model, social or marketing subscription has been purchased.

## Operational recovery

Use `/admin` and inspect the Business operations desk, source queue and research lab before intervening. D1 business runs store the source snapshot and result; Workflow platform completion alone does not prove a successful application result. Never reset a quota or alter evidence to force a green status.

Before schema changes obtain a D1 recovery bookmark. Prefer code rollback, preserving additive tables and later user activity. Do not restore the whole database over newer user data to undo a code defect. All release versions and live acceptance receipts belong in `cloudflare/RELEASE-*.md` and `cloudflare/tests/evidence/`.

The daily follow-up is the active Codex heartbeat `sponsor-intel-daily-improvement`. Its existence confirms scheduling configuration only; inspect actual execution before claiming it ran. Keep notifications for material completions, new actionable failures or a decision needed, and avoid repeating unchanged access blockers.
