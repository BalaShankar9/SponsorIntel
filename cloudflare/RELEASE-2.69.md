# 2.69 — Reviewed application-test controls

The application evaluator previously accepted a plain enabled toggle. It could not retain a review reason, reject a stale control revision or distinguish an exact retry from a new decision. A stale owner session could overwrite a later pause.

Resume and pause now require a reason, the observed comparison and revision, and an exact request identity. Resume additionally requires the prepared source/model profile, enabled business operations, no active or uncertain earlier application outcome, and an incomplete comparison without a failed attempted batch. Mutable checks repeat inside the D1 transaction. Pause remains possible with an active call, changed model configuration or business pause; it does not cancel a provider call already started.

Immutable review history records the action and exact profile separately from prior settings/audits. An identical retry returns its original decision and the current control state; it never reapplies a resume over a later pause. Conflicting replays and concurrent stale decisions are rejected. The owner form preserves an uncertain request for exact replay and reports when a subsequent decision applies. Old toggle-only payloads are rejected. There is no new workflow dispatch, call reservation, source identity or customer generation change.

Migration 0039 is additive: the existing enabled state, actor and timestamp stay unchanged; revision starts at zero and new review history starts empty. Earlier actions are not fabricated as new reviews.
