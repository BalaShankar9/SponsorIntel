# 2.87 — Structured company-report reviews

The genuine 19 October LinkedIn company-report critic returned an answer that failed the required evidence structure. Its saved diagnostic records a normal stop and ten completion tokens, but the rejected response was not retained. The precise missing or invalid field cannot be reconstructed. The original attempt and Held v2/r3 report remain unchanged; this release does not retry them.

Future daily attempts use `sourced-guides-report-schema-v8`. Only the existing untouched company-report review requests a JSON schema from the configured Cloudflare Llama critic. The schema requires every unit, its decision, explanation and bounded source references, plus the overall decision. Local checks still reject missing or duplicate units, unsupported source identifiers, invented quotations and accepted claims without evidence. A schema-shaped answer is not proof that the claims are supported or useful.

Each eligible report context retains the exact response format and hashes of its prompt, input and format, alongside the reviewer and unchanged provider parameters. The request is checked before reserving a model call. A missing or changed request stops that path; an unreviewed model configuration cannot select it. Existing v7 runs retain their original JSON-object request, and existing v6/v5 contexts keep their earlier behavior. Deploying a new policy cannot reserve a second daily attempt.

Future report-contract failures retain a trusted, bounded code such as `report_shape`, `unit_coverage` or `evidence_quote`, visible in the owner's retained structured step result. Raw rejected output and provider error text are not copied into diagnostics. Provider errors cannot supply these codes. Failed and uncertain calls stay charged and held; no automatic retry or rewriting loop is added.

Cloudflare documents JSON-schema output for the configured critic in [JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/) and its [Llama 3.3 model reference](https://developers.cloudflare.com/workers-ai/models/llama-3.3-70b-instruct-fp8-fast/). The documentation also warns that schema compliance is not guaranteed. A genuine future eligible run must establish actual provider behavior, valid review and separate content-quality acceptance. No production AI request is needed to deploy this change.
